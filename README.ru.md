## Что это

Без аккаунтов, рекламы и телеметрии. Свободное ПО под GPLv3.

Caelo говорит на [AmneziaWG](https://docs.amnezia.org/documentation/amnezia-wg/) с полным
набором параметров обфускации — мусорные пакеты, магические диапазоны заголовков и
сигнатурные пакеты AWG 2.0, из-за которых хендшейк выглядит как DNS, QUIC или SIP. Каким
из них ты в итоге пользуешься — вопрос, который приложение не задаёт.

Главный экран — кнопка, слово и строчка мелким шрифтом о том, что получилось. Настройки
существуют для случаев, которые автоматика не покрывает, и заходить туда не должно
требоваться.

## Архитектура

Всё, что принимает решения, живёт в Go-ядре: разбор и обновление подписок, проба и выбор
узлов, состояние соединения, статистика, расписание. Фронт на Flutter намеренно тонкий —
список, кнопка, экран настроек. Логика, существующая в обоих местах, — это логика, которая
однажды разойдётся сама с собой в вопросе, что подключено.

**Caelo не форкает ничего.** [sing-box](https://github.com/SagerNet/sing-box) подключён
обычным Go-модулем, а ядро регистрирует собственный эндпоинт `amneziawg` через его
публичный реестр. AmneziaWG берётся из
[amneziawg-go](https://github.com/amnezia-vpn/amneziawg-go), тоже как опубликован.
Обновление обоих — бамп версии, ребейзить нечего.

Альтернативой был форк `sagernet/wireguard-go` с переносом обфускации внутрь. Если мерить
от общего апстрима, эта ветка и `amneziawg-go` разошлись сопоставимо — примерно 1700 и
1800 существенных строк, — то есть сведение их в любую сторону это настоящая работа,
причём повторяемая на каждом релизе AmneziaWG. AmneziaWG — смысл проекта, поэтому свежей
должна оставаться именно эта зависимость.

| Путь | Что там |
| --- | --- |
| [`lib/`](lib) | Интерфейс. Flutter, Cupertino, один вид везде. |
| [`core/`](core) | Go-ядро: туннель, выбор, состояние. |
| [`packaging/`](packaging) | Превращение сборки в то, что ставится. |
| [`scripts/`](scripts) | По одному скрипту сборки на платформу. |

Зафиксировано: sing-box `v1.13.16`, amneziawg-go `v3.0.20260805`.

## Сборка

Каждый скрипт сначала собирает ядро, кладёт его туда, где загрузчик этой платформы ищет
сам, и только потом собирает приложение.

```bash
./scripts/build-macos.sh debug     # универсальный dylib в Contents/Frameworks
./scripts/build-android.sh debug   # по .so на ABI, внутрь APK
./scripts/build-ios.sh release     # статический xcframework в бинарь
./scripts/build-linux.sh debug     # .so в bundle/lib
./scripts/build-windows.sh debug   # .dll рядом с exe
```

Для Android нужен NDK — скрипт находит его в SDK, о котором Flutter и так знает. Отладочные
сборки iOS используют JIT и не запускаются без подключённого тулинга, поэтому там по
умолчанию release.

Любой из них можно запустить и без ядра — `flutter build <платформа>` соберёт интерфейс.
Приложение тогда честно скажет, что ядра нет, а не сделает вид.

### Попробовать туннель без приложения

```bash
cd core && go run ./cmd/caelo-probe -config /путь/к/tunnel.conf
```

Поднимает один туннель на userspace-стеке и тащит через него URL. Без прав, без интерфейса
на хосте, ничего вне процесса не заворачивается. Если напечатанный адрес — это адрес
эндпоинта, а не твой, значит сработало.

## Пакеты

| Платформа | Форматы |
| --- | --- |
| Android | по APK на ABI, универсальный APK для сайдлоада и `.aab` |
| Linux | `.deb`, `.rpm`, AppImage, `.tar.gz` |
| macOS | `.dmg`, `.pkg` |
| Windows | установщик, портативный `.zip` |

Четыре формата для Linux, потому что «Linux» — это не одна вещь. Ничего из этого пока не
подписано и не нотаризовано, и неподписанную сборку нельзя выдавать за релиз.
