# 0032 — Проверка IPv6 выхода до настройки VPN

## Почему

Issue #175: клиент объявлял IPv6 без проверки выхода. На сервере только с IPv4
браузер мог установить TCP внутри Xray, затем получить ошибку и не перейти
на IPv4. Состояние Connected при этом не гарантировало открытие страниц.

## Что изменено

Перед созданием интерфейса выполняется ограниченная по времени проверка TLS
на IPv6-адресах через выбранный VLESS. Достаточно одного проверенного ответа.
Результат привязан к точной конфигурации и передаётся в запуск туннеля один раз.
Остановка или новая подготовка отменяет предыдущую.

Android не объявляет неподтверждённое семейство: ОС блокирует его. На Apple
маршрут остаётся внутри VPN, а пакеты получают ICMPv6 no-route до TCP SYN-ACK.
Это даёт браузеру быстрый отказ без обхода VPN. AWG и системные туннели
десктопов сохраняют прежний путь.

## Проверка

Настоящие локальные Xray для четырёх вариантов, IPv4-only и dual-stack;
проверка сертификатов, таймаутов, отмены и передачи результата в запуск.
Пакетные тесты проверяют ICMPv6, границы MTU, отсутствие петель ошибок,
двунаправленный IPv4, закрытие дескрипторов и заголовки utun.
Полный путь клиентского сетевого стека через FD проверен для Vision и XHTTP
на macOS без создания системных интерфейсов и маршрутов.
