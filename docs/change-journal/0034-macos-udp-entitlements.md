# 0034 — UDP-права основного macOS-приложения

## Почему

Issue #178: release-сборка 0.3.16 показывала AWG-серверы недоступными.
Проверка обрывалась ещё до обращения к серверу: `listen udp4 :0: bind:
operation not permitted`. Системный журнал подтверждал отказ sandbox в
`network-bind`. В подписи основного приложения отсутствовал
`com.apple.security.network.server`; у debug-сборки и system extension
право было, поэтому прежний CI не обнаруживал дефект.

## Что изменено

В Release.entitlements основного приложения добавлено `network.server`.
Sandbox и остальные ограничения сохранены. Исходные права проверяются
в CI, фактические подписанные права app и extension — перед нотариализацией
и в приложении из готового DMG. Отсутствие права останавливает выпуск.

Отдельная проверка на macOS runner подписывает две минимальные sandboxed
программы: контроль без права должен получить EPERM при UDP bind, программа
с сетевыми правами release — открыть временный порт. Пакеты не отправляются,
системный VPN не создаётся. Запуск этого эксперимента ограничен CI.

## Проверка

- Проверка исходных entitlements падала до исправления и проходит после.
- Чтение подписи установленной прежней 0.3.16 отклоняет её по отсутствующему
  праву — это ожидаемый отрицательный контроль без запуска приложения.
- Локальный запуск `--exercise-bind` отклоняется до создания сокетов.
- На пользовательском Mac не запускались VPN/UDP-пробы, не менялись
  маршруты, DNS, firewall, подписанное приложение и действующие соединения.
