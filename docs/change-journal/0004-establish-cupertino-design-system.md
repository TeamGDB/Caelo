# 0004 — Реализация Cupertino-совместимой дизайн-системы

## Что требовалось

Реализовать согласованный вариант конфликтной задачи о визуальной стратегии:

- сохранить Cupertino как архитектурную основу;
- не подключать Material widgets, Material icon font и Inter;
- перенести совместимые дизайн-токены и responsive-правила;
- сделать брендовые примитивы только там, где они нужны текущему приложению;
- отметить задачу в GitHub Project;
- обеспечить понятный откат;
- собрать, протестировать и визуально проверить приложение.

## Почему

Полный переход на Material противоречит существующей архитектуре и потребовал бы переписать работающий UI без функциональной пользы для туннеля. Одновременно старые радиусы, hit targets и неограниченная ширина desktop-контента не давали достаточно устойчивой основы для развития интерфейса по спецификации.

## Как было сделано

### Архитектура и документация

- добавлен `docs/design-system.md` с зафиксированными решениями и правилами расширения UI;
- `CupertinoApp`, Cupertino-навигация, системный шрифт и `CupertinoIcons` сохранены;
- Material-зависимости не добавлялись;
- бизнес-логика и граница Flutter ↔ Go не менялись.

### Токены

- радиусы получили семантические роли `compact`, `control`, `card`, `dialog`;
- добавлены общие размеры для hit target, desktop content и dialogs;
- добавлены токены motion и stroke;
- расширена типографическая шкала при сохранении системного шрифта.

### Общие компоненты

- `CaeloPageSurface` — единый palette-derived фон;
- `CaeloContentWidth` — ограничение рабочей колонки до 560 logical px;
- `CaeloPanel` — общая поверхность карточек и форм;
- `CaeloIconButton` — единый icon-only control с областью 48 × 48 и semantics;
- `PowerButton` получил palette-driven gradient/glow и учитывает reduced motion.

### Переведённые экраны

- Home;
- Settings;
- Configuration;
- Diagnostic log.

Положение Settings, ручная локаль, server sheet и новые продуктовые экраны не реализовывались: они принадлежат отдельным задачам.

### Сборочная совместимость

- `flutter pub get` обновил две транзитивные записи lock-файла под Dart 3.12.2;
- Flutter 3.44 migrator добавил явные legacy-флаги `android.builtInKotlin=false` и `android.newDsl=false`, чтобы текущая Gradle-структура продолжала собираться без неявной миграции;
- для локальной Android-сборки установлен NDK 28.2 в существующий Android SDK; Flutter и Go использовались из временного `/tmp/caelo-toolchain-1000`.

## Проверка

- `dart format --set-exit-if-changed lib test` — пройдено;
- `flutter analyze` — замечаний нет;
- `flutter test` — 21 тест пройден;
- добавлены 4 widget-теста дизайн-системы: desktop width, compact width, 48 × 48 semantics и отсутствие Material в брендовых поверхностях;
- Go core собран для Android ABI `arm64-v8a`, `armeabi-v7a`, `x86_64`;
- собраны split debug APK и universal debug APK;
- в universal APK проверено наличие `libcaelo.so` для всех трёх ABI;
- universal APK установлен и запущен на Android 16 emulator;
- вручную просмотрены Home и Settings в light/dark; runtime-ошибок и визуальных overflow не обнаружено.

Linux desktop build не запускался: на хосте отсутствуют системные `clang`, `ninja`, `pkg-config` и GTK development headers, а `sudo` требует пароль. Это ограничение окружения, не ошибка исходного кода; Android-сборка выполнена полностью.

## Откат

Реализация находится в отдельном signed-off коммите `7331a18` (`Establish the Cupertino design system`). Её можно отменить отдельным `git revert 7331a18`, не откатывая подготовительный журнал и не переписывая историю ветки.

## Результат

Задача решена: текущий интерфейс использует документированную Cupertino-совместимую дизайн-систему, остаётся кроссплатформенным и не вводит Material или бизнес-логику в UI. Сборка, автоматические тесты и визуальная проверка успешны.
