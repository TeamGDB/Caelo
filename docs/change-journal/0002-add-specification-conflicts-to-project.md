# 0002 — Добавление конфликтов спецификации в GitHub Project

## Что требовалось

Все обнаруженные расхождения между существующим проектом Caelo и пожеланиями UI/UX-спецификации нужно было оформить отдельными задачами в GitHub Project №2.

## Почему

Конфликты затрагивают архитектуру, безопасность, UX и уже протестированное поведение. Их нельзя разрешать неявно во время реализации: каждое решение должно быть видимо в проекте и приниматься с учётом приоритета действующего кода и документации Caelo.

## Как было сделано

В GitHub Project `CaeloProject` созданы восемь draft-задач со статусом `Todo`:

1. Зафиксировать иерархию источников истины.
2. Согласовать Cupertino и единый Material-подобный визуал.
3. Согласовать композицию Home и центральную VPN-кнопку.
4. Согласовать положение Settings с desktop window chrome.
5. Оставить выбор серверов в Go-ядре.
6. Согласовать действие VPN-кнопки во время `disconnecting`.
7. Не переносить моковые аккаунты и админку как продуктовую логику Flutter.
8. Согласовать начальный язык и ручное переключение локали.

В каждой карточке записаны конфликт, действующая позиция проекта, список решений и критерий готовности. Перед созданием проверены существующие карточки; дубликатов не было. После создания отдельно проверено наличие всех восьми задач и статус `Todo`.

## Результат

Задача решена: все обнаруженные на этапе первичного аудита конфликты вынесены в отдельные отслеживаемые карточки проекта. Исходный код и конфигурация приложения не изменялись.
