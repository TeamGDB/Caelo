# 0023 — Подключить реальный backend подписок

## Что требовалось

Подключить готовый backend подписок к полю ссылки приглашения на первом экране
и получить от него реальные серверы вместо локальной имитации.

## Почему

Onboarding использовал `MockAccountGateway`: любая синтаксически корректная
HTTPS-ссылка открывала Home, но не выполняла запрос, не сохраняла подписку и не
добавляла серверы. Сам fetcher, parser, cache и node selection уже существовали,
однако не были соединены с пользовательским сценарием.

## Как сделано

- Фактический ответ backend сверен с `docs/subscriptions.md`: Caelo document v1,
  media type, метаданные узлов, usage и update interval соответствуют контракту.
- Реальный URL и bearer token не скопированы в issue, тесты, журнал, diagnostics
  или исходный код.
- Добавлен `SubscriptionAccountGateway`: он принимает только HTTPS URL без
  userinfo, добавляет подписку, требует успешного первого refresh и выдаёт
  доступ только после получения хотя бы одного пригодного узла.
- 403/404 преобразуются в `InvalidInvitation`; сетевые, TLS, timeout и format
  ошибки остаются временной недоступностью. Пустая запись после неудачного
  первого запроса удаляется.
- `SubscriptionFetcher.refresh` получил opt-in режим проброса ошибки. Обычные
  фоновые refresh по-прежнему сохраняют cache и ошибку, не ломая соединение.
- После успешного onboarding каталог серверов перечитывается до открытия Home.
  При последующих запусках cached nodes показываются сразу, затем подписки с
  истёкшим серверным интервалом обновляются в фоне.
- Android `INTERNET` permission добавлен в продуктовый main manifest: раньше он
  был только в debug/profile overlay и release не мог бы обратиться к backend.
- Локальная имитация QR удалена. До появления отдельного backend-контракта QR
  явно помечается недоступным и не создаёт фиктивный аккаунт.
- Добавлены unit/widget-тесты границы аккаунта и обновлены локализации.

## Решило ли задачу

Да: invitation URL теперь является реальным credential подписки, а не условием
для пропуска onboarding. После успешного ответа полученные серверы становятся
источником списка Home и конфигураций подключения.

## Проверка

- `flutter test` — 83 теста прошли.
- `flutter analyze` — замечаний нет.
- Android debug и release APK собраны вместе с native core; debug установлен
  на Android 16 emulator (API 36). В release APK отдельно проверено наличие
  продуктового `INTERNET` permission.
- Полный onboarding выполнен с предоставленным credential: backend вернул 7
  доступных на момент проверки узлов, cache сохранил их с интервалом 12 часов,
  Home показал реальные названия, страны, описания и измеренные задержки.
- Узел `Mett` выбран из списка и успешно поднял системный Android VPN; после
  проверки туннель отключён.
- Диагностический режим, временно включённый для проверки, выключен, а исходный
  журнал эмулятора восстановлен из резервной копии. Credential в журнал и
  репозиторий не попал.

## Откат

Изменение изолировано в ветке `37-real-subscription-onboarding`. Формат уже
существовавшего subscription cache не менялся. Отмена итогового коммита вернёт
локальный gateway; сохранённые subscription-файлы останутся читаемыми прежним
кодом.
