# 0029 — Подписки VLESS: Vision, XHTTP и согласование формата

## Что требовалось

- **#172.** Подключаться к узлам VLESS: TCP + REALITY + Vision, XHTTP + REALITY, XHTTP + TLS
  (в том числе через CDN), с отпечатком, который прислал сервер. Подписки — обычный список
  `vless://` (текст или base64) и документ Caelo, где AmneziaWG и VLESS в одном списке;
  способ объявить, что клиент умеет, кроме User-Agent. Существующие подписки AmneziaWG
  работают как раньше.
- Обновлять Xray должно быть просто; новые протоколы — добавлять в одном месте.

## Как сделано

- **Ядро.** VLESS — на Xray-core v26.11.9 (MPL-2.0), обычным Go-модулем; sing-box не
  подошёл — XHTTP только у Xray. Ссылка разбирается и проверяется в ядре
  (`internal/vless`): что нельзя выполнить как сказано — другой транспорт, неизвестный
  отпечаток, Vision не поверх TCP, выключенная проверка сертификата — отказ с причиной.
  Конфигурация для Xray — его JSON (стабилен между релизами), TUN — собственный вход Xray:
  дескриптор платформы на Android и Apple, своё устройство на Linux и Windows.
- **Реестр протоколов** (`internal/protocol`): Describe / Pin / Dial / Attach / Create.
  Проба, туннель в процессе, туннель на дескрипторе, системный туннель, `caelo_describe`
  и сервис сначала спрашивают реестр; путь AmneziaWG не менялся. Новые вызовы:
  `caelo_capabilities`, `caelo_validate`; версия Xray — в `caelo_version`, в ответе
  сервиса на `version`, в настройках и диагностике.
- **«Сервер жив»** для VLESS — байты от сервера (счётчик Xray); затихший туннель
  проверяется одним запросом, когда кто-то спрашивает, не чаще раза в минуту. Подключение
  считается состоявшимся после настоящего запроса через сервер.
- **Обновление Xray** — `scripts/update-xray.sh <тег>`: коммит тега (у Xray нет `/v26` в
  пути модуля), проверка, что слинкованный Xray сообщает этот релиз, таблицы атрибуции,
  тесты VLESS против настоящего сервера Xray той же версии. Go 1.27 — требование Xray.
- **Приложение.** Подписка читается в любом виде; вид — по ответу. Сборка, которая умеет
  VLESS, просит документ версии 2 и `text/plain` и шлёт `X-Caelo-Capabilities` во всех
  запросах к подписке; на Linux и Windows — пересечение с тем, что умеет сервис. Узлы VLESS
  проверяются ядром при обновлении. Пустая подписка и пропущенные узлы с причиной видны под
  списком серверов; подписка, в которой нечего запустить, — ошибка, прежний набор остаётся.
  Идентичность ссылки без id — тег, затем соединение без UUID. `profile-title` — название.
- **Платформы.** Android: адреса устройства в обоих семействах, ожидание первого запроса
  15 с. Apple: адрес сервера, разрешённый ядром, и IPv6 — только для протоколов из реестра.
  iOS: мягкий предел кучи Go 30 МБ при запуске VLESS (расширение ограничено ~50 МБ).
- **Контракт и пример.** `docs/subscriptions.md`: список ссылок, документ версии 2,
  объявление возможностей, правило идентичности, пустая / непригодная / неудачная.
  `examples/subscription-server` отдаёт узлы-ссылки по тому, что клиент объявил.

## Проверка

- `go test ./...` в `core/`: все четыре варианта через настоящий сервер Xray, поднятый в
  тесте (REALITY и TLS, Vision и XHTTP); неверный пользователь, непроверенный сертификат,
  закреплённый адрес, затихший туннель; проба и туннель в процессе на VLESS; реестр.
- Настоящие серверы Xray **26.11.9** (Vision, XHTTP/REALITY, XHTTP/TLS) и **26.10.31**
  (Vision, XHTTP/REALITY) с ядром клиента 26.11.9: отпечатки Safari, Chrome, Firefox;
  последовательные и параллельные HTTPS-запросы, файл 2 МиБ, DNS по UDP через сервер,
  выход через сервер; путь пробы приложения с задержкой.
- Сборки ядра: Android (3 ABI), iOS xcframework, macOS universal static, Linux, Windows.
  `swiftc -typecheck` расширения с новым заголовком.
- `flutter analyze`, `flutter test`: чтение всех видов подписки, base64, IPv6, Unicode,
  заголовки согласования, проверка ядром, пустая подписка, сохранение кеша, заметки.
- `examples/subscription-server/conformance.sh`: v1, v2, список ссылок — ридерами ядра и
  приложения.

**Не проверено:** туннель на устройствах (Android, iPhone, Mac с расширением) и системный
туннель Linux и Windows с VLESS — только сборка и тесты ядра; восстановление после смены
сети и отсутствие утечек DNS на устройстве; XHTTP/TLS на сервере 26.10.31 (на стенде у
этой машины нет CDN-домена).

## Цена

Библиотека ядра под Android выросла с ~10 до ~38 МБ на ABI (iOS и десктоп — сопоставимо):
Xray и его загрузчик JSON. Без загрузчика было бы ~22 МБ, но тогда конфигурацию пришлось бы
собирать из внутренних типов Xray, повторяя его логику, и обновление Xray перестало бы
быть бампом версии. Память на куче при работе — 2–4 МБ.

## Откат

Ветка `172-vless-subscriptions`. Ядро: убрать строку из `internal/protocol/all` — VLESS
перестаёт распознаваться, приложение перестаёт объявлять его и просить новые форматы, всё
остальное идёт путём AmneziaWG.
