# 0005 — Адаптация Home к UI/UX-спецификации

## Что требовалось

Сделать главный экран визуально ближе к UI/UX-спецификации, оформить работу отдельной задачей в GitHub Project и не использовать моковые серверы, страны, latency, таймеры или состояния соединения.

## Почему

Предыдущий Home честно отображал состояние туннеля, но центральная кнопка была заметно меньше и визуально дальше от заданного продуктового образа. При этом буквальный перенос server sheet был невозможен: текущий core ещё не предоставляет список серверов и контракт ручного выбора.

## Как было сделано

### GitHub Project

Создана задача «Приблизить главный экран к UI/UX-спецификации без моковых данных»:

- исполнитель: `GoldExtremal`;
- размер: `M`;
- во время реализации статус: `In progress`;
- в карточке явно записано, что server selector и тестовые данные не входят в задачу.

### Центральная VPN-кнопка

- диаметр адаптируется к viewport в диапазоне 176–224 logical px;
- реальная фаза `TunnelStatus.phase` показывается внутри кнопки;
- `connecting` и `disconnecting` получают вращающийся progress ring;
- `connected` получает palette-driven glow с пульсацией;
- при reduced motion ring становится статичным, а glow не пульсирует;
- сохранена действующая семантика `TunnelController.toggle()`;
- accessibility сообщает действие кнопки и не повторяет одинаковую подпись.

### Данные подключения

- нижняя connection panel появляется только при фактическом `status.node`;
- node, protocol и ping берутся только из `TunnelStatus`;
- отсутствующие protocol/ping не заменяются придуманными значениями;
- флаги, grade, страна и server list не добавлялись, потому что core их не сообщает;
- server selector отложен до появления отдельного Go API.

### Сохранённые ограничения проекта

- Cupertino и существующая дизайн-система сохранены;
- Material не добавлялся;
- предупреждение о туннеле только для процесса сохранено;
- Settings остаётся в безопасной нижней области desktop window chrome и поднимается выше реальной connection panel;
- бизнес-логика выбора серверов не переносилась во Flutter.

### Локализация и тесты

- добавлены RU/EN строки `currentConnection` и `latency`;
- generated localization-файлы обновлены;
- тесты адаптированы к status label внутри кнопки;
- добавлены проверки `connecting`, `disconnecting`, отсутствия панели без node, отсутствия выдуманного latency и русского compact viewport 320 × 640.

## Проверка

- `dart format --set-exit-if-changed lib test` — пройдено;
- `flutter analyze` — замечаний нет;
- `flutter test` — все 25 тестов пройдены;
- Go core собран для Android ABI `arm64-v8a`, `armeabi-v7a`, `x86_64`;
- собраны split debug APK и universal debug APK;
- финальный universal APK повторно собран после последней accessibility-правки;
- во всех трёх ABI universal APK подтверждён `libcaelo.so`;
- APK установлен и запущен на Android 16 emulator;
- Home вручную просмотрен в light и dark, runtime overflow и rendering exceptions не обнаружены.

Connected-состояние не подменялось тестовой конфигурацией ради скриншота. Его layout проверен widget-тестами через существующую границу `TunnelStatus`; production-код не содержит демонстрационных данных.

## Откат

Реализация находится в signed-off коммите `4d1607d` (`Bring Home closer to the product specification`). Точечный откат выполняется через `git revert 4d1607d`, без переписывания истории и без отмены базовой дизайн-системы.

## Результат

Задача решена: Home визуально приблизился к спецификации, оставаясь честным представлением реального core state. Моковые данные и дублирующая сетевая логика не добавлены.
